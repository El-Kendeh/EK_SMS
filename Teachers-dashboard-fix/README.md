# Teacher Dashboard — Full UI + Backend + Functional Audit

**Date:** 2026-06-26
**Scope:** The entire EK_SMS Teacher portal — every screen under `src/components/teacher/`, the hooks/context/API layer that feeds it (`src/api/teacherApi.js`, `src/hooks/useTeacher*`, `src/context/Teacher*`), and the backend that serves it (`backend_node/src/routes/teacher.js`, `controllers/teacherController.js`, the models and middleware it touches).
**Method:** 9 parallel audit agents, one per feature area, each tracing every screen end-to-end (UI → hook → API method → route → controller → model → DB). Findings then run through adversarial verifiers that confirm/refute/correct each one against the actual code.

> **Generated by a multi-agent workflow.** 9 finder agents completed. The verification pass completed for **3 of 9 areas** before the run hit the session token limit; the other 6 areas are **finder-only (unverified)**. I (Claude) then independently verified the two highest-stakes unverified claims by hand — both are **confirmed true**. Verification status is marked on every finding in [FINDINGS.md](FINDINGS.md).

---

## TL;DR

The Teacher Dashboard is a **polished facade over a largely non-functional core.** The UI work is genuinely good — skeletons, empty states, optimistic updates, animations, mostly-decent CSS. But trace almost any screen to the database and the chain is broken: wrong field names, wrong response shapes, params in the wrong place, stub data dressed up as real, and green "success" toasts firing while nothing persists.

Two defects make the whole thing worse than the sum of its parts, and **both are confirmed:**

1. **The dashboard crashes on mount.** `TeacherDashboard.js:183` calls `useSchoolContext()`, which throws when no `SchoolContextProvider` is mounted — and it never is. The call sits outside the ErrorBoundary, so the entire portal white-screens before any screen renders. **Until this is fixed, none of the other features are even reachable.**
2. **~14 backend models are used but never imported.** `teacherController.js` calls `Message.findAll`, `OfficeHour.create`, `BehaviourIncident.findAll`, `LessonPlan.create`, `PeerReview.findAll`, etc., but imports none of them, and `models/index.js` exports nothing. Every handler touching them throws `ReferenceError` at runtime — which the catch blocks then swallow into empty "you have nothing here" responses.

Fix those two first. They unblock roughly half the dashboard and make everything else testable.

## What actually works

Not everything is broken. These chains are genuinely wired to real data:

- **My Students roster** — `MyStudents` → `getClassStudents` → real student rows.
- **Timetable (read)** — reads real persisted `TimetableSlot` rows scoped to the teacher.
- **Academic Credentials** — `TeacherProfile` edit → `updateCredentials` → persists degrees/certs/bio/experience.
- **Print Class Roster** — reads the real roster (the QR it prints is dead, but the list is real).
- **Gradebook read, at-risk, class analytics KPIs, exams read, academic calendar** — the read queries run (subject to the contract-drift caveats below).

Everything else in scope is broken, faked, or unreachable.

## The nine systemic root causes

Most of the 120 findings collapse into a handful of patterns. Fix the pattern, not the symptom.

**A. The dashboard crashes on mount (VERIFIED).** Missing `SchoolContextProvider`. One-line-ish fix, unblocks everything. → shell-ux #1, ship-blocker #0.

**B. ~14 models used unimported (VERIFIED).** Single import block in `teacherController.js` resurrects messaging, threads, office hours, behaviour, lesson plans, peer review, spotlight, resources, channel prefs, whistleblower, access log, workload. → backend-integrity #1, ship-blocker #1.

**C. Frontend↔backend contract drift (pervasive — the #1 functional defect class).** Components read fields the controller never emits and POST shapes the controller rejects: camelCase vs snake_case (`dueDate`/`due_date`, `classId`/`class_id`), `data.history` vs `data.grades`, `data.entries` vs `data.gradebook`, bare array vs `{threads:[…]}` wrapper, path param vs `req.query`, `proposed_score` vs `requested_value`, missing required `request_type`. Reads render blank; writes 400. Appears in **every** area. Root: no shared API contract and no integration tests.

**D. Stub data shown as real + dishonest success toasts (a trust problem).** Grade stats `{0,0,0,0}`, attendance `70%`, parent rating `4.2/5`, grading timeliness `3d`, substitute tokens, counsellor referral, data exports, "grades permanently locked" — many actions flash green success while persisting nothing. Worst on a product whose whole pitch is grade integrity.

**E. Silent data loss on the trust-core actions.** Grade lock writes nothing (scores never sent). Attendance submit always shows success but the insert throws (missing `school_id`, wrong `notes`/`remarks` column). Exam-result save writes garbage and can null out a student's existing CA/midterm via a blind upsert.

**F. Missing tenant/ownership scoping (multiple IDORs).** `getStudentGradeHistory` has **no school scoping at all** — cross-tenant grade leak. Gradebook, lock, exam results, students, threads, and live-classes scope by `school_id` only with no class/subject ownership check → within-school cross-class read/write.

**G. The "grade integrity" core is unbacked.** No `is_locked`/`verification_hash`/`chain_position` columns; "lock" only sets `approval_status:'pending'`; receipts are fake; tamper counter is a heuristic guess; the `/verify` route 404s; the roster QR points nowhere. The product's central differentiator does not exist in the data layer.

**H. Error swallowing hides all of the above.** Dozens of catch blocks return `successResponse({items:[]})` and the API layer normalizes non-OK to empty arrays. A hard crash looks identical to "no data" — no loading/error distinction, no diagnostic signal.

**I. Dead code, orphan components, inert scaffolding, mobile gaps.** `QrAttendanceScanner`/`GradeReceiptModal`/`LockPreviewPane`/`StructuredGradeInput` never mounted; i18n provider with zero `t()` calls; `recommendResource`/`voiceDigest` endpoints with no UI; theme toggle that's a no-op; several CSS files with no `@media` queries / sub-44px touch targets, violating the standing responsiveness mandate.

## Fix order (full plan in [FIX-ROADMAP.md](FIX-ROADMAP.md))

- **P0 — Unblock:** mount `SchoolContextProvider`; import the missing models; stop swallowing errors so you can see what's broken.
- **P1 — Stop lying / stop losing data:** real grade-lock + persistence, attendance persistence, exam-result mapping, real `gradeStats`, and remove every fake success toast.
- **P2 — Security:** close the `getStudentGradeHistory` cross-tenant IDOR and add class/subject ownership checks everywhere; fix the whistleblower anonymity leak.
- **P3 — Contract drift:** reconcile every component↔controller shape; introduce an `api-spec` and integration smoke tests so this can't regress.
- **P4 — UX & polish:** kill dead buttons/orphan components/"Old feedback"/inert i18n; fix back/forward sync; fill the mobile breakpoints.

## How to read the verification badges in FINDINGS.md

- `✓ VERIFIED` — confirmed by an adversarial verifier against the code.
- `✓✓ VERIFIED BY CLAUDE` — I checked this one by hand in this session.
- `~ PARTIAL` — real, but the verifier corrected a detail (noted inline).
- `✗ REFUTED` — verifier found the claim is wrong; kept for transparency, do not action.
- `⚠ UNVERIFIED` — finder-only; the verification pass didn't reach it. Treat as a strong lead to confirm before a large change, not as gospel. (The two most important unverified findings were hand-verified and upgraded to `✓✓`.)
